# 成本核算规则（v1）

> 状态：已定稿（第一阶段基线）。配套《模型用量数据契约.md》；两者共同构成用量与成本的唯一口径来源。所有公式必须是可重复运行的纯函数，并由自动化测试覆盖。

## 1. 三态费用（硬规则）

任何费用数字必须能归入且仅归入以下一态：

| 费用态 | 定义 | 依据 |
|---|---|---|
| `actual` 实际费用 | 供应商账单或可靠实际费用数据确认的金额 | 事件 `cost.basis = "actual"`，`note` 说明账单依据 |
| `estimated` 估算费用 | 按已知价格版本与 §3 公式算出的金额，或登记者显式估算的金额 | 工具自动估算，或事件 `cost.basis = "estimated"` |
| `unknown` 未知费用 | 用量或价格依据不足，无法可靠核算 | 无 `cost`、无可用价格匹配；或 `cost` 缺 `amount` |

规则：

1. **actual 与 estimated 永不相加**。汇总时按币种分列两个桶，分别展示。
2. 一条事件的费用口径唯一（契约 §6.5 优先级）：登记 `cost` > 工具估算 > unknown。
3. **unknown 不是 0**。未知费用只计数（`unknownCostEventCount`），不产生金额，不得填入 0 元冒充"免费"。
4. 订阅套餐、免费额度、本地部署不折算成"真实调用单价"。第一阶段 Token 用量与货币成本分开统计；订阅制模型的货币成本记 `unknown`，Token 照常统计。

## 2. Token 汇总口径（硬规则）

- 总输入 Token = Σ`inputTokens`；总输出 Token = Σ`outputTokens`。
- `cachedInputTokens` 是输入总量的细分，`reasoningTokens` 是输出总量的细分。**汇总绝不把细分项二次累加进总量。**
- 明细视图（任务详情、模型统计）分别展示输入/输出总量与缓存/推理细分；占比由前端用细分 ÷ 总量计算，不新建总量字段。
- 事件级不完整记录（缺 Token 字段）在 Schema 层即被拒绝（契约 §7.4）；估算值必须带 `confidence: "estimated"`。

## 3. 估算公式

本阶段已闭合的核算要素索引（审查核实入口）：缓存输入价格回退规则见 §3.3 表第 1 行；推理 Token 价格回退规则见 §3.3 表第 2 行；细分 Token 的计算方式见 §3.2；金额精度与展示舍入策略见 §3.4。对应测试编号见《模型用量数据契约.md》§14（T04、T12、T13、T14）。

### 3.1 价格匹配

对每条事件确定唯一价格版本 `P`：

1. 事件显式带顶层 `priceId` → 用该价格（快照引用）。**该校验必须四要素一致**：`provider` 一致、`modelId` 一致、`occurredAt` 落在 `[effectiveFrom, effectiveTo)` 内；任一不满足报 `USAGE_PRICE_MODEL_MISMATCH` / `USAGE_PRICE_NOT_EFFECTIVE`，不得静默使用过期或错配价格（契约 §5 规则 5）；
2. 否则按 `(provider, modelId)` 匹配 `effectiveFrom ≤ occurredAt < effectiveTo`（`effectiveTo = null` 视为开放区间）的价格；
3. 无匹配 → 该事件费用 `unknown`；
4. 多条匹配（价格有效期重叠）→ 校验层 `USAGE_OVERLAPPING_PRICE` 已拦截，不会进入计算；
5. 事件带 `cost`（含 `cost.priceId`）时不再走自动估算；`cost.priceId` 仅作登记费用的计价依据，适用同一套四要素校验；顶层 `priceId` 与 `cost.priceId` 同时存在且不一致 → `USAGE_PRICE_REF_CONFLICT`（契约 §6.6）。

### 3.2 单事件估算金额（币种 = P.currency）

设 `u = P.unitTokens`：

```
nonCachedInput = inputTokens - cachedInputTokens
cachedInput    = cachedInputTokens
nonReasoning   = outputTokens - reasoningTokens
reasoning      = reasoningTokens

estimatedAmount =
      nonCachedInput / u * P.inputPricePerUnit
    + cachedInput    / u * P.cachedInputPricePerUnit
    + nonReasoning   / u * P.outputPricePerUnit
    + reasoning      / u * P.reasoningPricePerUnit
```

即：

- 输入拆成"非缓存输入"与"缓存输入"两段分别计价；
- 输出拆成"非推理输出"与"推理输出"两段分别计价；
- 每段单价除以 `u` 换算成每 token 单价。

### 3.3 单价缺失的回退假设（必须显式标注）

| 缺失项 | 回退规则 | 假设标识 |
|---|---|---|
| `cachedInputPricePerUnit` | 缓存输入段按 `inputPricePerUnit` 计价 | `cached_input_price_fallback_to_input` |
| `reasoningPricePerUnit` | 推理段按 `outputPricePerUnit` 计价 | `reasoning_price_fallback_to_output` |
| `cachedInputTokens` | 视为 0（无缓存命中声明） | — |
| `reasoningTokens` | 视为 0（无推理声明） | — |

发生回退时，事件的估算结果携带对应假设标识，并逐级汇总进 `UsageBucket.assumptions`；UI 的统计口径说明必须展示这些假设。**回退估算是估算，不得冒充供应商实际账单。**

**回退假设记录规则（2026-10-22 项目负责人批准）**：

> 回退假设记录规则：仅当对应计价分段的 Token 用量大于零、该分段单价缺失，且实际使用回退单价完成费用估算时，才在 `assumptions` 中记录相应的回退标识。对应分段的 Token 用量为零时，该分段费用为零，不触发单价回退，也不记录该项回退假设。此规则仅规范假设标记的触发条件，不改变既定的费用计算公式。事件已登记 `cost` 时，仍遵循事件费用优先级，不重复执行自动估算。

本规则只约束假设标记的触发条件，不涉及 Schema 或费用公式变更（保持 Schema v1）。实现与测试按此规则闭环：分段为零不标记、分段大于零且实际回退时标记、金额与等价显式单价完全一致。

### 3.4 金额精度

- 单价与中间计算用双精度浮点；单事件金额展示四舍五入到 4 位小数；汇总金额展示 2 位小数。
- 汇总 = 各事件金额之和（不做二次四舍五入到事件级），保证任务明细之和与版本/模型汇总数值一致。

## 4. 价格版本管理

- 价格快照不可变：费率变化 = 新增一条 price 记录，`effectiveFrom` 指向变化生效时刻；禁止编辑历史 price。
- 事件通过 `priceId` 显式绑定快照，或按 `occurredAt` 落入价格有效期。历史事件因此永远按当时的费率可复核。
- `basis` 字段记录不可变依据（定价页快照、账单周期、公告链接等），是审计入口。
- 同一 `(provider, modelId)` 的有效期不得重叠；重叠即校验失败，防止同一调用匹配到两个价格。

## 5. 多币种规则

- 不同币种的金额**不相加**。汇总结构 `costActual`/`costEstimated` 以币种为键分列（`{ "CNY": 1.23, "USD": 0.45 }`）。
- 第一阶段不做汇率转换：没有明确汇率与转换规则时，分别展示；UI 在统计口径说明中标注"多币种分列，未做汇率换算"。
- 事件的 `cost.currency` 与所引用 price 的 `currency` 不一致 → `USAGE_CURRENCY_MISMATCH` 校验失败。
- 币种字面量采用 ISO 4217 三位大写字母（Schema 层强制）。

## 6. 汇总一致性要求

以下数值必须由同一纯函数链路产出，保证互相一致（自动化测试逐项断言）：

1. 任务详情的 Token 与费用 = 该任务全部事件的累加；
2. 版本汇总 = 其下全部任务汇总之和；
3. 模型统计 = 按 `(provider, modelId)` 分组的全部事件累加；
4. 整体统计 = 全部事件累加，且等于各版本汇总之和、各模型汇总之和、各角色汇总之和；
5. 筛选后的任务列表摘要 = 筛选集合的汇总，口径与整体一致。

## 7. 统计口径说明（UI 固定文案要点）

界面必须持续可见或可展开地说明以下口径，避免把估算当账单：

1. 实际费用与估算费用分列展示，不相加。
2. 估算费用按价格版本与公式计算；公式与假设（§3.3）在说明中列出。
3. 未知费用只计数不计价；订阅/免费额度/本地部署模型的货币成本为未知。
4. Token 口径：输入/输出为总量，缓存/推理为细分，不重复累计。
5. 多币种分列，未做汇率换算。
6. 示例与测试数据有明确标注，不与真实消耗混淆。

## 8. 第一阶段明确不做

- 汇率换算与统一币种视图。
- 订阅套餐摊销、免费额度抵扣模拟。
- 供应商账单自动导入与对账（待自动采集阶段独立立项）。
- 任何把估算结果回写为"实际费用"的路径。

## 9. 变更规则

- 公式、回退假设、币种规则的任何变化必须升契约版本或保持向后兼容，并同步更新：契约文档、《模型用量数据契约.md》、`src/usage.ts` 实现、Schema、UI 口径说明与测试。
- 测试必须覆盖：三态分离、细分不重复累计、回退假设标注、多币种分列、价格版本历史可追溯、汇总五层一致性。
- 测试基线以《模型用量数据契约.md》§14 矩阵（T01–T15）为准：本文件 §2 口径、§3 公式与回退、§4 价格版本、§5 币种规则的每一项都必须有对应编号的自动化测试；独立验收代理按矩阵逐项独立检查，不得仅凭文档新增说明判为通过。
